## 一、bsk 的文件大小双限制（最要命）

**bsk 的 `upload` 不是"把路径交给浏览器"，而是"暂存一份副本 → WebSocket 分块传输 → 扩展 → 塞给浏览器"。**

```
transfer.begin → transfer.chunk → transfer.finish
```

所以有**两道硬限制**：

| 限制 | 实测报错 |
|---|---|
| **单文件 512 MiB** | `file size 765599973 exceeds transfer limit 536870912` |
| **会话累计 512 MiB** | `session transfer staging exceeds limit 536870912` |

**会话额度按会话独立计**——开新会话就重置。但**单文件上限跨会话依然存在**。

**而且额度记账是缓存的**：手动删掉 `~/.bsk/run/transfers/` 里的文件**不会**让它重新计算。

### 单文件本机交付

原生上传优先。原生暂存容量不足，或已确认存在组件文件对象的兼容问题时，可以把用户指定的一份素材交给同一官方编辑页。先确认账号、草稿、目标入口、当前控制权，以及之前的尝试是否已经选中或上传。权限、登录验证、实际遮挡或人工接管需要先在原流程中解决。

从 skill 根目录启动助手，`--origin` 填这一次平台编辑页的确切来源。

```bash
./scripts/inject-large-file.sh "$FILE" --serve-only --origin https://channels.weixin.qq.com
```

首行 JSON 提供 `url`、`origin`、`name`、`size` 和 `type`。助手仅在 `127.0.0.1` 临时监听，只向该来源交付指定文件；一次成功读取或超时后退出。保持助手进程到该文件读取完毕。地址只在本次操作内部使用。

**DSH 的页面操作仍由已绑定的 `bsk_*` 会话执行。** 使用[素材选择适配器](../scripts/media-file-input.js)，按下列顺序在同一草稿和同一卡片完成交付。

1. 同步并核对目标账号、草稿、可见上传区、卡片比例及已有素材。把这张卡片的实际 DOM 节点作为 `panel`，助手首行的 JSON 对象作为 `ticket`。解析回执时保留文件名原文，用 JSON 序列化传值。
2. 读取适配器源码，将整个函数表达式作为 `adapter` 放入本轮 `bsk_interact` 的 `evaluate` 表达式，通过当前 `contextId` 和观察或精确的业务条件保护调用。在页内执行 `await adapter('prepare', kind, panel, ticket)`，`kind` 取 `video` 或 `cover`。`prepared` 表示本机已读出并核对字节，尚未触发选文件事件。
3. 在原标签页重新同步，确认用户已交还控制、草稿与目标卡片仍相同，再用同一份函数和参数调用 `adapter('select', kind, panel, ticket)`。如有精确定位的文件框，可作为第 5 个参数传入。素材或控件发生变化时保留现场，重新核实。
4. `selected` 和 `already_selected` 都转入[视频上传验收](verification.md#视频上传)或[封面验收](verification.md#封面)。上传器可能在消费文件后清空输入框，应结合平台进度判断。控件仍被遮挡、权限被拒或页面只接受原生文件选择时，交还当前卡片的原生选择框。

适配器采用输入框所属窗口的文件类型。微信视频号的首帧、时长和卡片问题见[视频号上传排查](#视频号上传排查)。

## 二、bsk 会话空闲 5 分钟自动关闭

默认配置：

```
SESSION IDLE  5 分钟      ← 会话空闲就自动关闭 Agent Window
DAEMON IDLE   10 分钟
```

**后果**：你埋头调一个平台，其他平台的窗口超时被关。关窗时 Chrome 发现页面有未保存内容，弹出「**离开此网站？**」保护提示——**B站 和视频号的草稿就是这么丢过一次。**

看到「离开此网站？」时，先分清是当前编辑页的主动跳转，还是窗口在收尾或空闲时被关闭。仅凭这句话无法判断草稿是否已保存。先查同一份草稿的保存回执或列表记录，再按[留页交接或关闭专用会话](../SKILL.md#7-留页交接或关闭专用会话)处理。

长任务若需要调长空闲时间，应在下次开工前、确认同一 daemon 没有进行中的会话或待人工接手的窗口时设置。下面的重启会关闭该 daemon 的所有 Agent Window：

```bash
bsk daemon restart --session-idle 4h --daemon-idle 8h
```

当前已有上传或待交接的编辑页时，先保留页面，不能用重启处理眼前的弹窗。

## 三、Chrome 的调试横幅

BrowserSkill 挂上调试器时，Chrome 会在**所有窗口**顶部显示：

> 「BrowserSkill 已开始调试此浏览器」

**它只是提示，不影响功能**，但很占空间且污染无关窗口。

**压制方式**：Chrome 必须以启动参数启动：

```bash
open -a "Google Chrome" --args --silent-debugger-extension-api
```

**⚠️ `open -a` 只在 Chrome 未运行时才传参数**——已在运行的话只是切到前台，参数被忽略。必须先完全退出 Chrome。

**已做成启动器**：见 `setup/chrome-silent/`。

**别改 Chrome 本体**（替换 `MacOS/Google Chrome` 二进制）——破坏签名，且每次自动更新都会失效。

## 四、BrowserSkill 扩展需要「允许访问文件网址」

没有这个权限时，文件上传会报（**两种措辞都遇到过，都要认出来**）：

```
cdp_failed: {"code":-32000,"message":"Not allowed"}
phase: set_files
```

2026-09-29 实测的另一种措辞（默认 `input` 模式）：

```
error: the browser could not attach the staged file to the input
hint: check that BrowserSkill has Chrome's 'Allow access to file URLs' permission; otherwise use `bsk request-help`
details: {"code":-32000,"message":"Not allowed"}
```

以及 `--mode drop` 下的第三种：

```
error: the browser could not complete the native file drop
details: {"code":-32602,"message":"Not allowed"}
```

**关键：`bsk status` 和 `bsk doctor` 在这个状态下【全绿】。** 光看状态发现不了，必须实传一次文件（见 SKILL.md 步骤 0 的探针）。

小文件也在 `set_files` 阶段被拒时，结合错误码核对当前扩展的文件访问权限。页面几何命中错误按第十三节排查。

由用户在实际浏览器配置中打开 `chrome://extensions`，找到 BrowserSkill 的详情页，核对「允许访问文件网址」。

⚠️ **这个权限开了之后，已经存在的 bsk session 不会自动复活** —— 重新 `bsk session start` 再传。

## 五、B站 封面的双面板陷阱

B站 封面有 **4:3（首页推荐）** 和 **16:9（个人空间）** 两个独立面板。

**坑一：上传前不确认激活面板 → 图进错槽**

实测错误序列：

```
① 传 横版-4x3.png   → 进 4:3 ✅
② 点 16:9 面板      → 没激活成功（没验证）
③ 传 16x9.png       → 又进 4:3 ❌ 把正确的图覆盖了
④ 真正激活 16:9
⑤ 再传 16x9.png     → 进 16:9 ✅
```

**结果**：4:3 槽里躺的是 16:9 的图，被按 4:3 裁切后"放大被切"，很难看。

**修法**：**上传前必须验证目标面板是 active 状态。** 面板的 active/inactive 类有时不暴露，此时靠点击目标面板元素（mousedown → mouseup → click）并观察哪个槽的图变了来确认。

**坑二：点「完成」时平台提议"同步"**

> 「检测到个人空间封面（16:9）未修改。是否将「4:3封面」的改动同步到「16:9封面」？」
> 　`不同步，手动编辑`　`确认同步`

**如果点「确认同步」，4:3 的图会覆盖掉正确的 16:9。**

**永远选「不同步」**（除非确实要两张一样）。

**坑三：只看"有图"就以为对了**

分别核对 `cover-list.extra`（首页 4:3）和 `cover-list.main`（空间 16:9）的绑定、卡片预览及对应来图。相同素材可能复用 CDN 地址，签名也可能单独刷新。交付时给草稿入口，或给可公开使用的封面地址。

## 六、视频号的「保存草稿」不保存视频标注

## 七、B站 会自动塞不相关的标签

实测被塞过：

```
V2（文件名）、生活记录、记录、日语现场、音乐现场、LIVE
```

**它们会占掉 10 个标签名额。** 实测一次塞了 3 个（`日语现场/音乐现场/LIVE`），导致目标标签只进了 7 个。

**做法：上传后先删掉无关标签（`.label-item-v2-container` 里的 `svg.close`），再补目标标签。**

⚠️ **空标签输入框时不要按 Backspace** —— B站 会理解成"删除最后一个标签"。

## 十一、平台字段在上传期间的可编辑性不同

| 平台 | 上传中能填？ |
|---|---|
| 小红书 | ✅ 标题 / 话题 / 声明 / 封面 |
| 抖音 | ✅ 标题 / 声明 |
| B站 | ✅ 标题 / 标签 / 声明 |
| **视频号** | ❌ **锁定**：「文件上传中，请等待完成后再编辑」 |

**所以「上传中预填」策略只适用于前三家。视频号必须等传完。**

### 视频号上传排查

按下列顺序检查当前视频或开着的封面卡片，每一行对应不同的处理动作。

| 页面现象 | 检查和处理 |
|---|---|
| 原生选择或拖放报 `covered` / `not topmost` | 在当前标签同步，查看截图、打开的弹窗及可见上传区。核对命中的是本次编辑器，区分真实遮挡和 wujie 组件边界。先处理真实遮挡。仍无法确认目标时，请用户在原上传区选文件。遇权限错误按第四节处理。 |
| 文件名、字节数已匹配，本地还读不到时长 | 查看编辑页的 `document.visibilityState`、视频的 `readyState`、`duration`、`error` 和上传进度。后台页、`readyState=0`、时长为空时，先让**原编辑页**可见，观察同一份原片。读出与探测一致的时长表示元数据可用。原片有明确的不支持或解码错误时才讨论换素材。 |
| 已有进度、平台显示上传中或转码中 | 保留原会话和视频，等待完成提示或字段解锁，再核对当前视频。仅出现播放器、缩略图或本地 `blob:` 时仍缺平台回执。 |
| 封面文件已选，预览仍是视频第一帧 | 比较用户图片的辨识细节、比例及当前卡片的预览。wujie 编辑器可能使用自己的 `window`：已授权交付的 `File`、`DataTransfer` 和 `input` / `change` 事件均使用该输入框的 `ownerDocument.defaultView` 构造。看到所选图后再确认，回读同一主卡片的平台图片。 |
| 点过保存，还没有独立回执 | 从另一张任务标签打开同一账号的草稿箱，按描述或标题与时间核实该条。最后在编辑页设置本条视频判定出的标注，读回控件并交接。 |

同类故障两次无进展时，先确定最后有证据的阶段。记录实际的页面状态和缺少的回执，再改变处理方式。

## 十二、平台会改版

实测期间遇到的改版：

- **B站封面编辑器**新增「智能生成封面」弹窗，要先点「不使用」才能进手动上传
- **B站封面**从"两个并排上传区"改成"4:3 / 16:9 双面板"
- **小红书封面**引入新版编辑器（带模板/贴纸），大视频会失败
- **视频号封面随成片方向变化**（2026-11-18 核对）。竖屏成片显示一个共用的 3:4 入口，横屏成片截图显示主页 3:4、分享 4:3 各自有「编辑」。此前把观察到的单槽归为整个平台改版，漏掉了横屏分支。判定见[视频号封面](platforms.md#视频号封面)。
- **小红书「内容类型声明」**（2026-09-29 实测）**四个选项里没有"无需声明"**（虚构演绎 / 笔记含AI合成内容 / 内容包含营销广告 / 内容来源声明）——**留空就是"无需声明"的表达**

**所以这份文档里的选择器都有保鲜期。失效时先怀疑改版，不要怀疑自己的操作。**

- **抖音视频上传与封面（2026-11-18）**　视频上传页已找不到 `div.drag-over`。当次快照中「点击上传 或直接将视频文件拖入此区域」的按钮可接收 MOV。两张封面重新打开草稿后分别显示在各自卡片的 `img` 上。
- **小红书横图 4:3 裁剪与原创开关（2026-11-18）**　上传 4:3 横图到小红书封面编辑器时，默认仍选中左侧「3:4」比例框，必须切「裁剪 → 4:3」后再点「完成」；原创声明原生 checkbox 为 `0×0` 不可见，须点 `.custom-switch-card .d-switch`，并在《原创声明须知》弹窗勾选 `.originalContainer .d-checkbox-simulator`。
- **B 站登录接口跨域与自制授权（2026-11-18）**　在 `member.bilibili.com` 调 `https://api.bilibili.com/x/web-interface/nav` 时必须传 `{ credentials: "include" }`，否则会漏带 Cookie 误报 `code=-101`。「内容为自制：未经作者允许，禁止转载」（`.auth-content`）在「创作声明」下拉底部，可与「含AI生成内容」同时勾存；主表单缩略图用 `.cover-img` CSS `background-image` 渲染。
- **视频号第二卡继承提示与媒体静音（2026-11-18）**　横屏视频设完个人主页 3:4 后点分享卡片 4:3「编辑」可能先浮出「使用此素材作为封面？」，须点「直接编辑」再上传 4:3 图。操作期间应对主文档及 `wujie-app` shadow root 内的 `<video>`/`<audio>` 设 `muted = true; pause()`（不改 `volume`），留页交接前保持暂停并还原 `muted = false`。

## 十三、隐藏的 file input 会被 bsk 拒掉（四个平台全踩）

四个平台的 file input **全都是隐藏的**（`0×0` / `opacity:0` / `display:none`）。直接拿 input 当 target：

```
error: target element has no visible geometry
hint: rerun snapshot and choose a visible child ref, or wait/scroll/reload before retrying
```

**这不是权限问题，也不是操作问题——那个元素本来就不占位。**

**修法**：指向**可见的投放区**。小红书用 `div.drag-over`，抖音用当前快照中「点击上传 或直接将视频文件拖入此区域」的按钮 ref，B站用 `.bcc-upload-wrapper div.upload-area`，视频号用 `--ref` 指可见区。各平台的目标定位见[文件上传](selectors.md#文件上传)。

⚠️ 这条和第四条（文件访问权限）**报错完全不同**，别混：几何问题报 `no visible geometry`（本地就能判断），权限问题报 `Not allowed`（要动浏览器设置）。

## 十四、B站 有些词是「仅话题」，在标签框里会静默消失

实测（2026-09-29）`WorkBuddy`：标签框里**打字 → 回车 → 文字被清空、标签不落地、连报错都没有**。

同批的 `DeepSeek` / `Kimi` / `AI` 都正常，所以**不是大小写、不是英文、不是输入法的问题**。

**根因**：B站 有些词只作为**话题**存在（WorkBuddy 话题页 993.4 万次播放），不能当自定义标签。

**解法（实测有效）**：

```
参与话题  →  搜索更多话题  →  搜索框输入词  →  选中该话题  →  确定
```

走完这条路，`WorkBuddy` 会出现在 `.label-item-v2-content` 里（标签 7 → 8 个，存盘复查后仍在）。

**兜底**：这条路也走不通时，**留成一条明确的待办报给 Jack，绝不悄悄换成别的词**（oil-oil 文档的明确要求：*Do not silently drop or replace the requested tag.*）。

## 十五、bsk session 会因为「中断」或「超时」整个消失

实测两次踩到：

| 触发 | 后果 |
|---|---|
| `bsk request-help` 被 abort（用户在 Agent Window 按了停止） | session 直接没了 |
| 长时间不操作 | session idle 超时关闭（默认 5 分钟，见第二条） |

先区分会话空闲关闭与真人接管。空闲关闭时，在同一账号的草稿箱核对已经保存的条目，从该条尚未完成的字段续做。长任务的空闲预算应在开工前设置。

收到真人接管或停止信号时，按[硬边界](../SKILL.md#硬边界)停下全部浏览器操作并通知用户。简报写「编辑器占用」和最后核实的进度；平台状态不能说明是谁在打字。用户明确交还后，等原会话控制权就绪再同步。若会话届时已经失效，先查草稿箱。
